HOW TO READ THE CALIPER
-----------------------
Jaws are open at GRIPPER_OPEN throughout (tag_pick_place.py:1596), so the
span is constant and cancels.

At the park, measure the horizontal gap from each fingertip's INNER face to
the block face it points at:

    gapL = left  fingertip inner face  ->  block face
    gapR = right fingertip inner face  ->  block face

    offset along the closing axis = (gapR - gapL) / 2

Jaw span and block width both cancel in the difference -- neither has to be
known, and neither contributes error. That is what gets a cheap caliper to
~0.3 mm.

NOTE at this stage the park is the STANDARD hover: flange 0.1855, fingertips
0.0510, i.e. 25 mm ABOVE the block's top face (+0.0260). That is awkward and
it is exactly what the 16:15 edit fixes by dropping the park to 8 mm above
the face. Do the best you can here -- this number is the BASELINE we are
trying to beat, so a mediocre reading is still the right reading.


TRIAL A -- CALIPER SIGMA, 5 runs (target 15:10-15:50)
-----------------------------------------------------
Run from the scripts directory:  cd ~/swarm/swarm_project/src/swarm_pkg/src/scripts

There is NO --confirm flag. Confirm is ON BY DEFAULT; --yes is what turns it
off (tag_pick_place.py:2370, dest="confirm", action="store_false"). So the
command is simply:

  python3 tag_pick_place.py --skip-pick --any-block \
      --zone-origin 0.2032 0.0000 0.0 --zone-yaw 180 \
      --note "s1 trialA caliper sigma"

Run it five times. Between runs do NOT touch the mat or the block.

YOU WILL HIT TWO PROMPTS PER RUN:

  1. ":2029  ENTER = go to the hover"
     The arm has NOT moved yet. Nothing to see. Just ENTER.

  2. ":2107  parked HERE, NN mm above the grasp height"
     THIS is where you caliper. Measure gapL and gapR, write them down,
     then ENTER. --skip-pick (:2131) then records and stops -- nothing
     descends.

DO NOT TYPE ANY NUDGE IN TRIAL A. Not a correction, not a zero -- nothing.
The caliper is the measurement; the nudge is the thing we are replacing,
because it is a control action pushed through a ~3.5 mm dead band and
fitting it fits the dead band. Trial B is the only place you type numbers.

WHY FIVE RUNS WITH NOTHING TOUCHED. Each run redoes the full 4-still survey,
so the five give five INDEPENDENT vision draws of a scene that did not move.
That is what sigma is measuring, and vision fusion noise (~0.8-1.0 mm, from
the measured view_spread_m of 1.6-3.1 mm over 3-5 views) is expected to be
the LARGEST term in it -- bigger than the caliper. Moving the block would
add your own placement error to that and measure something else.

  run |  gapL  |  gapR  | offset=(gapR-gapL)/2 | notes
  ----+--------+--------+----------------------+------------------
   A1 |        |        |                      |
   A2 |        |        |                      |
   A3 |        |        |                      |
   A4 |        |        |                      |
   A5 |        |        |                      |

  mean offset ______   sd (sigma) ______   <-- THE NUMBER THAT GATES THE PLAN

  sigma <= 1.0 mm  -> 1-2 mm target is available, continue as planned
  sigma  1-2 mm    -> continue, but expect ~2-3 mm; say so before Saturday
  sigma  > 2 mm    -> STOP. The instrument is the problem, not the model.

TRIAL B -- J1 DIRECTION TEST, 6 parks (target 15:50-16:15)
----------------------------------------------------------
THE BLOCKER. move_arm_to defaults unidirectional=False (pick_place.py:3381)
and no call site in tag_pick_place.py passes it -- so the arm arrives at the
park resting on whichever flank of J1's slack the previous move left it on,
and it never gets the J1_RESIDUAL_BIAS_DEG = 1.10 correction either (that is
applied only inside j1_unidirectional_approach, pick_place.py:3340).

The test needs no code. A nudge round trip that NETS TO ZERO leaves
commanded_world identical but makes the arm arrive from the opposite side.
Any caliper difference is therefore pure lost motion.

At the demo pose the bearing is 0, so TANGENTIAL is world +Y.

  Start one run as in trial A (same command). ENTER through the first
  prompt. At the SECOND prompt -- the parked one -- type these in sequence,
  measuring where marked. Each entry re-parks the arm and re-prompts, so you
  stay in the loop until you press ENTER on its own.

  B-plus  (arrives travelling +Y):   0 -8   <enter>
                                     0 +8   <enter>    then MEASURE
  B-minus (arrives travelling -Y):   0 +8   <enter>
                                     0 -8   <enter>    then MEASURE

  Net nudge is 0.0 in both cases, so the commanded point is the SAME.
  Repeat the pair three times (6 measurements total), then ENTER to finish.

  pair |  B-plus offset  |  B-minus offset  |  difference
  -----+-----------------+------------------+-------------
    1  |                 |                  |
    2  |                 |                  |
    3  |                 |                  |
                                    mean difference ______

  |difference| ~ 6 mm   -> BLOCKER CONFIRMED. Apply unidirectional=True.
                           Also probably explains open item #2: the
                           "+X wants -0.0088, +Y wants 0.0000" tangential
                           split is 8.8 mm = one backlash width, measured at
                           bearings 90 deg apart.
  |difference| < 1 mm   -> the blocker is not real; tell me before I edit,
                           because the tangential model changes completely.

  8 mm is chosen to clear the ~3.5 mm J1 dead band (1 deg at r=200) in both
  legs. If the arm visibly does not move on a leg, raise it to 12.

TANGENTIAL COUPLING CHECK -- CONFIRMED, and the constant is REMOVED
  With the J1 fix live, the jaws parked ~3 mm toward world +Y of the block
  at the demo pose (operator correction: 0 -3). Sign and magnitude both as
  predicted: at bearing 0, JAW_TANGENTIAL_OFFSET_M = -0.0033 commands
  flange_y = y + 0.0033, so with J1's +-3.4 mm no longer cancelling it, the
  push stood bare.

  JAW_TANGENTIAL_OFFSET_M  -0.0033 -> 0.0

  This is a REMOVAL of a term shown to be spurious, not a new fit. The old
  comment recorded the split it could not explain -- "+X wants -0.0088 and
  +Y wants 0.0000, and a radial model cannot have both" -- which is 8.8 mm,
  one backlash width, at bearings 90 deg apart. There was no radial
  quantity there to model.

  The ~+0.9 mm that remains belongs to J1_RESIDUAL_BIAS_DEG, not here.
  Folding it in would repeat DESCENT_BIAS_Z doing GRASP_OFFSET_Z's job.

MEASUREMENT PARK ADDED -- --measure-clearance-mm, default 8
  Normal hover -> straight-down cartesian 17 mm -> flange 0.1685, fingertips
  8 mm above the block's TOP FACE instead of 25. Referenced to the top face,
  not the grasp: at the grasp the tips are level with the block CENTRE,

  THE +4.7 mm RADIAL WAS NEVER REAL. FK flange radius error, from the
  transcripts, at the settled park:
      before the J1 fix   -1.15 mm  (14 parks)
      after the J1 fix    -1.40 mm  (5 parks, sd 0.09)
  Identical -- and it must be, J1 is the base yaw and cannot move the radius.
  So the radial improvement is the MEASUREMENT METHOD, not the robot. A 4.2 mm
  apparent shift at 25 mm above the top face is a 9.5 deg viewing angle, which
  is just what standing at a bench looking down at an arm gives you.

  Note the SIGN, because it is the give-away: FK says the flange lands 1.2-1.4 mm
  SHORT of commanded, i.e. INWARD. The hover eyeball reported +4.7 mm OUTWARD.
  It was not noisy, it was wrong in direction.

  WHAT THIS DOES AND DOES NOT INVALIDATE. Only the NUDGE column is affected.
  The constants that matter were fitted from tape and caliper, not eyeballs:
    JAW_RADIAL_OFFSET_M -0.0199  -- 8 grasps, BLOCK taped, measured from the base
    ORIGIN_RADIAL_BIAS_M -0.0285 -- surveyed origin vs TAPED truth
    DESCENT_BIAS_Z -0.001        -- zone survey, digital caliper
  The -1.2 mm FK radius error is independent support for JAW_RADIAL_OFFSET_M
  being about right. The history is not poisoned; its nudge column is.
